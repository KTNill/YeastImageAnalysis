# YeastImageAnalysis

本プロジェクトは、熊本大学 谷研究室の要望を受け、酵母の細胞数や細胞面積、油分量等を効率的かつ定量的に解析することを目的として開発した画像解析システムです。

透過光画像（BF）のみを用いた基本的な「細胞数カウント」「細胞面積（サイズ）測定」から、蛍光画像（FL）やPI蛍光画像（PI）を組み合わせた「油脂蓄積量・生産率の算出」「壊死細胞割合（生死判定）の定量」まで、研究目的に合わせて解析を実行できるGUIアプリケーションとなっています。

内部のエンジンには Cellpose によるAIセグメンテーションを採用し、細胞領域・油脂領域・壊死領域を高精度に検出。解析結果を統計データ（CSV）や可視化された統合マスク画像として一括出力します。

## 主な機能

- **フレキシブルな解析モード:** 用途に合わせて「細胞数のみ（BF）」「細胞＋油脂（BF+FL）」「細胞＋生死（BF+PI）」など解析項目を自在に選択可能
- **高精度な細胞カウント・サイズ定量:** 透過光画像（BF）から細胞領域を自動分離し、細胞数および個々の細胞面積（px）を一括算出
- **油脂蓄積・分布定量:** 蛍光画像（FL）から細胞内油脂量・総油脂量・細胞内外分布を算出
- **壊死細胞割合（生死判定）算出:** PI蛍光画像（PI）と細胞領域の重なりから壊死細胞数を自動判定
- **画像フォルダ一括自動解析:** 選択したフォルダ内の全画像を自動でペアリングして連続処理
- **一括自動環境構築:** 初回起動時に実行環境（`python_env`）および初期モデル（`models`）をGoogle Driveから全自動ダウンロード・セットアップ
- **1枚テストプレビュー機能:** 本解析前に単一画像でパラメータやノイズカットの効き具合をリアルタイムで確認可能
- **詳細設定機能:** 目的別（共通・細胞・油脂・壊死）の設定ファイルによる細かなパラメータ調整や独自のカスタムモデルへの差し替え対応
- **カスタムモデル作成・学習連携:** ユーザー自身の手によるアノテーションおよび追加学習用GUIへの連携
- **結果の一括CSV保存:** 画像ごとの詳細データおよび全体統計サマリー（平均・標準偏差）をCSV形式で保存

## 主な用途・解析パターン

本システムは、お手持ちの画像データや実験目的に応じて以下のパターンで活用いただけます。

| 解析パターン         | 使用する画像 | 得られる主なデータ | 主な用途例           |
|----------------|---|---|-----------------|
| **1. 細胞解析**    | 透過光 (BF) のみ | 細胞数、総細胞面積、平均細胞面積 | 細胞の増殖評価、サイズ分布測定 |
| **2. 細胞・油脂解析** | 透過光 (BF) + 蛍光 (FL) | 細胞数、油脂占有率、総生産率、油脂保有細胞割合 (%) | 細胞の油脂蓄積効率評価     |
| **3. 細胞・壊死解析** | 透過光 (BF) + PI蛍光 (PI) | 細胞数、壊死細胞数、壊死細胞割合 (%) | 細胞の破砕率評価        |

## 起動方法

### Windows（推奨）

プロジェクト直下のバッチファイルを実行するだけで起動できます。

```text
起動ファイル.bat
```

**全自動環境構築機能:**

ローカルに `python_env`（Python環境）や `models`（初期解析モデル）が存在しない場合、Google Driveから全自動でダウンロード・解凍・配置が行われます。利用者が手動で環境構築やモデルの配置を行う必要はありません。

### Pythonから直接起動する場合

自身で構築した仮想環境を有効化したうえで、以下を実行してください。

```bash
python main.py
```

## 設定ファイル

解析設定は `config/` ディレクトリ内の以下のCSVで機能ごとに管理されます。初回起動時、ファイルが存在しない場合はデフォルト設定で自動作成されます。GUI上の「⚙」ボタンからも直接編集・保存が可能です。

- `config_common.csv`: 共通設定（画像識別子、GPU使用の有無、統合画像の描画色など）
- `config_cell.csv`: 細胞検出に関する設定（モデルパス、細胞径、閾値、最小サイズなど）
- `config_lipid.csv`: 油脂検出に関する設定（モデルパス、ノイズカット、平均輝度閾値、ガンマ補正など）
- `config_necrosis.csv`: 壊死検出に関する設定（モデルパス、最小重複割合、ノイズカット、ガンマ補正など）

**主な設定項目（一部）:**

| 項目名 | 内容 | 該当ファイル |
|---|---|---|
| 細胞モデルパス | 細胞検出用のモデルパス（空欄でデフォルトのcpsam使用） | config_cell.csv |
| 油脂モデルパス | 油脂検出用のモデルパス（空欄でデフォルト使用） | config_lipid.csv |
| 壊死モデルパス | 壊死検出用のモデルパス（空欄でデフォルト使用） | config_necrosis.csv |
| 透過光画像識別子 | BF画像を識別する文字列（デフォルト:`_BF`） | config_common.csv |
| 蛍光画像識別子 | FL画像を識別する文字列（デフォルト:`_FL`） | config_common.csv |
| PI蛍光画像識別子 | PI画像を識別する文字列（デフォルト:`_PI`） | config_common.csv |
| GPU使用 | GPUを使用する場合は `1.0`、使用しない場合は `0.0` | config_common.csv |

## 画像ファイルの命名規則

各画像は設定CSVの識別子に基づいて自動でペアリングされます。**BF画像の識別子がファイル名末尾にあること**を基準として探します。

デフォルト設定の例:
```text
透過光画像識別子: _BF
蛍光画像識別子: _FL
PI蛍光画像識別子: _PI
```

ファイル構成の例（フル解析の場合）：
```text
sample01_BF.tif  (細胞用: 必須)
sample01_FL.tif  (油脂用: 任意)
sample01_PI.tif  (壊死用: 任意)
```
※ BF画像のみで解析を行う場合は `sample01_BF.tif` のみで実行可能です。

対応する画像拡張子: `.png`, `.jpg`, `.jpeg`, `.tif`, `.tiff`

## 解析結果

解析を実行すると、選択した画像フォルダ内に以下の形式で結果保存用の新規フォルダが作成されます。（GUIの「実験メモ」に入力した文字列はフォルダ名に組み込まれます）

```text
result_メモ内容_YYYYMMDD_HHMMSS/
```

出力内容の例：
```text
result_test1_20260803_140000/
├── config_common.csv                  # 実行時の設定バックアップ
├── config_cell.csv                    # 実行時の設定バックアップ
├── config_lipid.csv                   # 実行時の設定バックアップ
├── config_necrosis.csv                # 実行時の設定バックアップ
├── analysis_summary.csv               # 解析結果と統計のCSV
├── 01_cell_sample01_BF.tif            # 細胞マスク画像
├── 02_lipid_sample01_BF.tif           # 油脂マスク画像（FL選択時）
├── 03_combined_sample01_BF.tif        # 細胞・油脂統合画像（FL選択時）
├── 02_necrosis_sample01_BF.tif        # 壊死マスク画像（PI選択時）
└── 03_combined_necrosis_sample01_BF.tif # 細胞・壊死統合画像（PI選択時）
```
※ ノイズカット等の前処理機能が有効な場合、`00_clean_...` などの前処理適用済み画像も合わせて出力されます。

### 出力CSVについて

`analysis_summary.csv` には、画像ごとの解析値と全体統計（平均・標準偏差）が出力されます。実行した解析モードに応じて必要な項目が出力されます。

- **ファイル名**: 解析対象の基本となるBF画像名
- **細胞解析**: 細胞数, 細胞面積(px)
- **油脂解析**: 油脂占有率, 総生産率, 細胞内油脂割合(%), 油脂保有細胞数, 油脂保有細胞割合(%)
- **壊死解析**: 壊死細胞数, 壊死細胞割合(%)

## 指標の定義

本システムでは、研究の評価軸となる各種指標を以下のように定義して算出しています。

```text
油脂占有率 (蓄積度)  = 細胞内の油脂総面積 / 細胞の総面積
総生産率 (効率)      = 全油脂面積(細胞外含む) / 細胞の総面積
細胞内油脂割合 (分布)= (細胞内の油脂面積 / 全油脂面積) * 100
油脂保有細胞割合     = (油脂を含んでいる細胞数 / 全体の細胞数) * 100
壊死細胞割合         = 壊死と判定された細胞数 / 全体の細胞数
```

## GUIの使い方

1. アプリを起動する。
2. `画像フォルダを選択` をクリックし、解析対象の画像群が入ったフォルダを選択する。
3. フォルダ名に使用される `実験メモ` を必要に応じて入力する。
4. 実行したい解析（「細胞解析(BF)」「油脂解析(FL)」「壊死解析(PI)」）のチェックを入れる/外す。
   ※ 単純な細胞数カウントのみ行いたい場合は「細胞解析(BF)」のみチェックを入れます。
5. 各項目の横にある `⚙` ボタンから、しきい値や使用モデルなどの詳細設定を確認・変更する。
6. `1枚テストプレビュー` をクリックし、プレビュー対象（前処理後 / マスク / マージ）を切り替えながら、パラメータが適切か確認・調整する。
7. 設定が完了したら `解析開始` をクリックする。
8. 進捗バーとログで解析状況を確認する。
9. 解析完了後、ログに表示された「解析結果保存先」フォルダを開きデータを確認する。

## カスタムモデルの作成・追加学習

本システムでは、デフォルトモデルでうまく検出できない画像に対して、ユーザー自身で正解データ（アノテーション）を作成し、独自の解析モデル（カスタムモデル）を学習させることができます。

1. **GUIの起動:**
   同梱の `モデル学習GUI起動.bat` をダブルクリックして実行します。
   （初回起動時のみ、画面表示に必要な追加パッケージ群が自動的にインストールされます。）
2. **主な手順:**
   - Cellpose公式のGUIが立ち上がります。
   - 画面内に画像をドラッグ＆ドロップ（またはメニューから読み込み）し、マウスを使って細胞や油脂の正解輪郭（マスク）を描画または修正します。
   - 上部メニューの `Models` ➔ `Train new model` を選択して、アノテーションした画像を元に追加学習を行います。
   - 学習が完了して保存されたカスタムモデルファイルを本システムの `models` フォルダに配置し、設定画面からモデルパスを書き換えることで、次回の解析から利用可能になります。

## 解析モデルの管理と再利用機構

- **モデルの差し替え・更新:**
  `models` フォルダが存在しない初回起動時のみ初期モデルが自動配置されます。その後はユーザーが自由にお手元のカスタムモデルを追加・上書き・差し替えて運用できます（BATファイルが既存モデルを上書き消去することはありません）。
- **高速なモデル再利用:**
  解析開始時に設定CSVは再読み込みされますが、モデル設定（モデルパスやGPU指定）に変更がない場合はメモリ上の既存モデルをそのまま再利用し、起動時間を大幅に短縮します。

## GPU利用について

`config_common.csv` の `GPU使用` の値により処理デバイスを切り替えます。

- `1.0`: GPUを使用（推奨）
- `0.0`: GPUを使用しない（CPUのみ）

CUDA環境が構築されている場合は自動でCUDAを優先します。また、macOS環境ではMPS（Metal Performance Shaders）が利用可能な場合にMPSを使用します。有効なGPU環境が見つからない場合は自動的にCPUフォールバックして解析を続行します。

## 注意事項・リポジトリ管理

- **大容量データのGit管理除外:**
  容量圧迫や転送制限を防ぐため、`python_env` や `models` などの大容量フォルダ・ファイルは Git の管理対象外（`.gitignore`）となっています。自動ダウンロード機能により、リポジトリのクローン直後でも起動ファイルを実行するだけで自動復元されます。
- **画像サイズの完全一致:**
  BF画像、FL画像、PI画像は同一視野のものであり、解像度・画像サイズが完全に一致している必要があります。
- **開発環境との分離:**
  プロジェクト内の `python_env` フォルダはバッチ起動用の固定実行環境です。開発時のIDE（PyCharmやVSCode等）の環境とは分けて管理してください。

## トラブルシューティング

### ダウンロードエラーが発生する
ネットワーク接続およびファイアウォール等の通信制限を確認してください。

### `operator torchvision::nms does not exist` のようなエラーが出る
Python環境内で `torch` と `torchvision` のバージョン不整合が起きているか、インストールが破損している可能性があります。
バッチファイルで使用しているPython環境から以下を実行し、バージョンが正しく対応しているか確認してください。

```bat
.\python_env\python.exe -m pip show torch torchvision
.\python_env\python.exe -c "import torch; import torchvision; print(torch.__version__, torchvision.__version__)"
```
